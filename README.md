# قِسمة — Qisma

منصة رقمية لإدارة **الملكية المشتركة للعقارات** بين الورثة والشركاء: سجل موحّد للملكية، الأموال، الإثباتات، الاعتراضات، الإقفال الشهري، التوزيعات، والقرارات.

هذا المستودع يحتوي على تطبيق كامل جاهز للتطوير الحقيقي:

```
qisma/
├── backend/    Node.js + Express + TypeScript + PostgreSQL (Prisma ORM)
└── frontend/   React + TypeScript + Vite + Tailwind (واجهة عربية RTL)
```

جميع الوحدات الخمسة عشر في خارطة الطريق (MVP) مبنية فعليًا: المصادقة، العقارات، الملكية، الشركاء، السجل المالي، الإثباتات الإلزامية، الاعتراضات، الإقفال الشهري، التوزيعات، القرارات والتصويت، سجل التدقيق (Audit Log)، الإشعارات، المستندات، والتقارير.

---

## 1. البنية التقنية

### Backend (`/backend`)
- **Express + TypeScript**, منظم كوحدات (modules) لكل ميزة تحت `src/modules/*`.
- **Prisma ORM + PostgreSQL** — المخطط الكامل في `prisma/schema.prisma` (24 نموذج بيانات).
- **JWT** للمصادقة، **RBAC على مستوى العقار** (OWNER / MANAGER / ACCOUNTANT / VIEWER) عبر `middleware/propertyAccess.ts`.
- **Audit trail** منفصل عن سجل النشاط: كل تعديل حساس (مبلغ، ملكية، إقفال) يُسجَّل بقيمته قبل/بعد في `AuditLog`.
- تحميل ملفات (إثباتات، مستندات) عبر `multer` إلى القرص محليًا (`/uploads`) — يسهل استبدالها بـ S3 لاحقًا.
- منطق أعمال حقيقي: تقييم التصويت المرجّح بنسب الملكية (`utils/decisionRules.ts`)، حساب التوزيعات، إقفال الشهر مع منع التعديل بعد القفل.

### Frontend (`/frontend`)
- **React 18 + TypeScript + Vite + Tailwind**، واجهة عربية RTL بالكامل مع تسميات إنجليزية للحقول التقنية (Status، JD...).
- تصميم مخصص (طبقة "سجل عقاري"): ألوان ink/parchment/brass/sage/clay، خط Cairo للعناوين وIBM Plex Sans Arabic للنصوص، وأرقام مالية بخط IBM Plex Mono بأرقام تصنيفية محاذاة (tabular).
- كل وحدة MVP لها صفحة كاملة تتواصل مع الـ API الحقيقي (لا بيانات وهمية في الواجهة، فقط seed حقيقي في القاعدة).

## 2. التشغيل المحلي

### المتطلبات
- Node.js 20+
- PostgreSQL 14+ (محليًا أو عبر Docker)

### الخطوة 1 — قاعدة البيانات
أنشئ قاعدة بيانات فارغة، مثلاً عبر Docker:
```bash
docker run --name qisma-db -e POSTGRES_USER=qisma -e POSTGRES_PASSWORD=qisma -e POSTGRES_DB=qisma -p 5432:5432 -d postgres:16
```

### الخطوة 2 — الـ Backend
```bash
cd backend
cp .env.example .env        # عدّل DATABASE_URL/JWT_SECRET إذا لزم
npm install
npm run prisma:migrate      # ينشئ الجداول
npm run seed                # بيانات تجريبية: عمارة النور + 4 شركاء
npm run dev                 # http://localhost:4000
```

بيانات الدخول التجريبية بعد الـ seed:
| البريد الإلكتروني | كلمة المرور | الدور |
|---|---|---|
| mohammad@qisma.test | password123 | مالك/مدير العقار |
| ahmad@qisma.test | password123 | مالك |
| khaled@qisma.test | password123 | مالك |
| sara@qisma.test | password123 | مشاهدة |

### الخطوة 3 — الـ Frontend
```bash
cd frontend
cp .env.example .env        # يشير افتراضيًا إلى http://localhost:4000/api
npm install
npm run dev                 # http://localhost:5173
```

سجّل الدخول بأي من الحسابات أعلاه، أو أنشئ حسابًا جديدًا من `/register`.

## 3. جولة سريعة في الميزات

1. **لوحة التحكم** (`/app`) — نظرة على المحفظة الكاملة عبر كل العقارات.
2. **عقار → نظرة عامة** — هيكل الملكية، "أين ذهبت الأموال؟"، آخر النشاطات.
3. **الملكية والشركاء** — النسب الحالية، السجل التاريخي الكامل، إدارة الأدوار، تحديث الملكية (يحفظ القديم تلقائيًا).
4. **المالية** — تسجيل إيراد/مصروف، رفع إثبات، طلب تأكيد من طرف مستقل (رابط عام بدون تسجيل دخول)، توثيق العملية.
5. **الإثباتات** — طلبات الإثبات وحالتها، وجدول الفروقات (المسجَّل مقابل تأكيد الطرف الآخر).
6. **الاعتراضات** — فتح اعتراض على أي عملية، نقاش، حل مع تصحيح اختياري للمبلغ (موثّق في Audit Log).
7. **الإقفال والتوزيع** — معاينة أرقام الشهر الحالي، إقفاله، إنشاء توزيع تلقائي حسب نسب الملكية، تسجيل الدفعات، وصفحة "حصتي".
8. **القرارات** — إنشاء قرار، تصويت مرجّح بنسبة الملكية أو موافقة المدير حسب قواعد العقار، تنفيذ القرار.
9. **المستندات، التقارير، النشاط/Audit Log** — كما في خارطة الطريق الأصلية.

## 4. ملاحظات للتطوير المستقبلي (V1.5 / V2 / V3 من خارطة الطريق)

- استبدال تخزين الملفات المحلي بـ S3/Cloud Storage (`backend/src/utils/upload.ts`).
- إشعارات بريد إلكتروني/SMS فعلية بدل التخزين في القاعدة فقط (`backend/src/utils/notify.ts`).
- تكامل بنكي ومطابقة كشوف حساب تلقائية.
- تطبيق موبايل يستهلك نفس الـ REST API.
- اكتشاف عمليات غير طبيعية بالذكاء الاصطناعي فوق سجل الـ Ledger الحالي.
